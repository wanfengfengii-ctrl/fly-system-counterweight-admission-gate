# 剧场吊杆配重装载安全链路

剧场装台场景：多名技师可能在吊杆两端同时登记配重片。本系统保证**逐片装载的原子裁决**——
任何并发下合计重量都不会突破吊杆核定值，配重片标识全库只能成功登记一次，被拒绝的请求绝不落库。
装台调整时还可以把**已登记的配重片整体转移**到另一根吊杆：只改归属、不清空、不重新登记，
原始重量与登记时间保留。装台复核发现实物标称重量录错时，可以直接**修正当前吊杆明细中的重量**：
不删除配重片、不重新登记，配重片标识与最初登记时间保留。演出拆台时，技师可在当前吊杆明细中
**确认拆下**一片配重：容量立即释放，但记录不删除——配重片标识、重量、归属吊杆、最初登记时间与
拆下时间全部保留以备追溯，历史唯一标识仍被占用、不能再登记。

演出前值守技师还要独立完成**吊杆日检**：系统为每根吊杆保存按营业日期归档的巡检记录，
内容包括制动器、钢丝绳、限位装置三项结果及异常说明。技师在日检区域选择吊杆、营业日期并勾选
检查项后提交，**结论（合格 / 需处理）只能由服务端判定**——三项全部正常为合格，任一项异常为
需处理，客户端不能指定结论；任一项异常时异常说明不能为空。每根吊杆同一营业日期只接纳一份
记录，重复提交返回已完成提示；未知吊杆、未来日期、缺少异常说明一律按错误信封拒绝，失败请求
不留下巡检记录，也不改变配重装载、转移、修正和拆下数据。

## 架构

- **web**（React + Vite）：选择预置吊杆，录入配重片唯一标识与整数克重量，展示当前总重、
  剩余量、已接纳明细或明确拒绝原因。明细中每片配重片提供“转移”“修正重量”与“确认拆下”：
  转移选择目标吊杆确认后即调用转移接口；修正重量输入新的整数克数确认后调用修正接口，并展示
  修正结果；拆下需在明细中点“确认拆下”后再于确认面板二次确认，成功后刷新总重、余量与在杆
  明细，并展示本次释放的重量。日检区域独立于此：选择吊杆与营业日期、勾选三项检查项、
  按需填写异常说明后提交，页面展示服务端判定的结论、检查明细与记录时间，并可按吊杆
  查看最近日检记录。页面所有状态均来自接口，刷新后与数据库一致。
- **api**（FastAPI + SQLAlchemy）：在 PostgreSQL 中以 `SELECT ... FOR UPDATE` 行级锁
  串行化同一吊杆上的并发装载；转移时按吊杆编号**固定顺序**锁定源、目标两根吊杆，在同一事务
  内确认配重片仍属于源杆并校验目标余量，随后只更新现有装载记录的归属。修正重量在同一事务内
  先锁定路径指定的吊杆，再确认装载记录仍归属于该杆，以新旧重量差重新核算容量后只更新重量。
  拆下在吊杆行锁内确认记录仍处于在杆状态（`removed_at IS NULL`）后只写入拆下时刻：不删除
  记录，容量随本片重量立即释放。容量汇总、明细查询与转移 / 修正裁决只认在杆记录；配重片
  唯一标识含已拆下记录在内全库占用，旧数据升级（补 `removed_at` 列）时统一视为在杆。
  日检是独立的巡检模型：结论由服务端根据三项检查结果判定后落库，`(batten_id,
  inspection_date)` 数据库唯一约束保证每根吊杆同一营业日期只接纳一份记录，并发重复
  提交由约束兜底拒绝。
- **db**（PostgreSQL 16）：保存吊杆（G-01 / G-02）、成功装载记录与日检记录三张表。

Compose 只定义 **web** 与 **api** 两个应用服务（db 为数据基础设施）。

## 验收规则

- 固定夹具：`G-01`（核定 30000 克）、`G-02`（核定 50000 克），服务启动时自动建表播种。
- 单片重量仅接受 100～25000 克，且必须是 JSON 整数——字符串 `"100"`、小数 `100.0`
  等一律 422 拒绝，不做隐式转换。
- 接纳条件：当前总重 + 本片重量 ≤ 核定值（恰好相等允许）。
- 配重片标识全库唯一，只能成功一次；失败请求不写入数据库。
- 配重片标识先规整再裁决：首尾空白不参与标识（`" CW-1 "` 与 `"CW-1"` 视为同一标识）；
  仅含空白的标识、含换行等不可见字符的标识一律 422 拒绝。装载 / 转移 / 修正 / 拆下
  路径中的装载编号必须是正整数，非数字、负数或零一律 422 并明确提示装载编号不合法。
- 转移：把一片已登记配重片从源吊杆移到目标吊杆，**只更新现有装载记录的归属**，
  原始重量与登记时间保留；目标杆当前总重 + 本片重量 ≤ 核定值才允许。
  目标吊杆编号先规整再裁决：仅含空白的目标编号 422 拒绝并明确提示转移目标参数
  不合法，不会误报吊杆不存在。
  固定顺序锁定两根吊杆，相反方向的并发转移不会死锁；配重片已被其他终端移走时
  返回 `POSITION_CHANGED`，数据库保持原归属。
- 修正重量：把当前吊杆上一片已登记配重片的标称重量改为新的整数克数，
  **只更新现有装载记录的重量**，配重片标识与最初登记时间保留；新重量沿用单片
  100～25000 克范围，按新旧重量差重新核算容量（恰好达到核定值允许写入）。
  与装载、转移在同一吊杆行锁上串行；记录已被其他终端转移时返回
  `POSITION_CHANGED`，越界或导致超载时拒绝，数据库中的原重量保持不变。
- 拆下（演出拆台）：在当前吊杆明细中确认取下一片配重，**不删除记录，只写入拆下时刻**
  （`removed_at`）；容量随本片重量立即释放，而配重片标识、重量、归属吊杆与最初登记
  时间全部保留备查。容量汇总、在杆明细与转移 / 修正裁决只认在杆记录；已拆下记录的
  历史唯一标识仍全库唯一、不能再次登记；旧数据升级时统一视为在杆。与装载 / 转移 /
  修正同一套吊杆行锁串行：记录已被其他终端转移时返回 `POSITION_CHANGED` 并由页面
  重载；对已拆下记录重复拆下时幂等返回明确结果，`released_grams` 为 0、不重复释放容量。
- `POST /api/reset`：清空装载记录与日检记录、恢复两根空吊杆，供每个验收场景开始前调用。
- 日检：每根吊杆同一营业日期只接纳一份记录，重复提交返回 `INSPECTION_EXISTS` 已完成
  提示，原记录不被覆盖；同一营业日期不同吊杆互不影响，同一吊杆不同营业日期各自归档。
  结论只能由服务端判定：三项检查全部正常为合格（`PASS`），任一项异常为需处理
  （`NEEDS_ATTENTION`），请求体中没有结论字段，客户端夹带的结论字段一律不采信。
  任一项异常时异常说明不能为空：仅含空白或零宽空格等不可见字符（控制、格式、
  行/段分隔符）的说明在历史里看起来为空，一律视为未填写——异常时按
  `MISSING_ABNORMALITY_NOTE` 422 拒绝，全部正常时按无说明归档；
  未来日期（`INVALID_DATE` 422）、未知吊杆（`BATTEN_NOT_FOUND` 404）明确拒绝；
  失败请求不留下巡检记录，也不改变配重装载、转移、修正和拆下数据。

## 接口摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/battens` | 两根吊杆的总重 / 剩余量 |
| GET | `/api/battens/{id}` | 单杆明细（含已接纳配重片列表） |
| POST | `/api/battens/{id}/loads` | 逐片装载裁决，体：`{"piece_id": "...", "weight_grams": 20000}` |
| POST | `/api/battens/{id}/loads/{load_id}/transfer` | 转移已登记配重片，体：`{"target_batten_id": "G-02"}`；响应含 `source` / `target` 两杆刷新后的总重与余量 |
| POST | `/api/battens/{id}/loads/{load_id}/correct` | 修正已登记配重片的重量，体：`{"weight_grams": 15000}`；响应含新旧重量与该杆刷新后的总重与余量 |
| POST | `/api/battens/{id}/loads/{load_id}/remove` | 确认拆下（二次确认在页面完成），无请求体；响应含 `released_grams`（本次释放重量，重复拆下为 0）、`already_removed`、`removed_at` 与该杆刷新后的总重与余量 |
| POST | `/api/battens/{id}/inspections` | 吊杆日检归档，体：`{"inspection_date": "2026-09-14", "brake_ok": true, "rope_ok": false, "limit_ok": true, "abnormality_note": "..."}`；结论由服务端判定，响应含结论、检查明细与记录时间 |
| GET | `/api/battens/{id}/inspections` | 按吊杆查看最近日检记录（按营业日期倒序，`limit` 默认 10） |
| POST | `/api/reset` | 恢复两根空吊杆（同时清空装载与日检记录） |

拒绝响应均带 `accepted: false` 与 `reason`：
`INVALID_WEIGHT`（422）、`INVALID_INPUT`（422）、`SAME_BATTEN`（422）、
`MISSING_ABNORMALITY_NOTE`（422）、`INVALID_DATE`（422）、
`PIECE_ID_EXISTS`（409）、`OVER_CAPACITY`（409）、`POSITION_CHANGED`（409）、
`INSPECTION_EXISTS`（409）、
`BATTEN_NOT_FOUND`（404）、`LOAD_NOT_FOUND`（404）。

## 测试（均为真实接口 / 真实数据库，无假接口）

```bash
# pytest：真实并发事务（两个 20000 克并发投向空 G-01，必须仅一笔成功，
# 总重固定 20000 克、剩余量固定 10000 克）
docker compose exec api pytest -v

```

```bash
cd api && API_BASE_URL=http://localhost:${API_PORT:-8000} python -m pytest -v

```
